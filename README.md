# 레거시 사내 게시판 → Spring Boot 3 전환 사례

2012년에 만들어진 뒤 담당자가 퇴사해 아무도 손대지 못하던 사내 게시판을
**구조는 살리면서 최신 스택으로 옮기고, 장애 원인 8가지를 모두 고친** 예제입니다.

> 실제 고객사 코드가 아니라, 25년간 현장에서 반복해서 본 문제들을 재현해 만든 데모입니다.

| 구분 | 전 (`legacy-before`) | 후 (`modern-after`) |
|---|---|---|
| 자바 | 1.7 | 21 |
| 프레임워크 | Spring 4.3 + XML 설정 + web.xml | Spring Boot 3.5 (설정 파일 1개) |
| 화면 | JSP + 스크립틀릿 | Thymeleaf (자동 이스케이프) |
| DB 접근 | 문자열로 이어 붙인 JDBC | MyBatis 바인딩 변수 (기존 SQL 자산 유지) |
| 배포 | WAR + 외부 Tomcat | 실행 가능한 JAR 하나 |
| DB 계정 | 소스에 하드코딩 | 환경 변수 (`application-prod.yml`) |
| 테스트 | 없음 | 회귀 테스트 9개 |

## 고친 문제 8가지

| # | 레거시 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | 검색창에 `' OR '1'='1` 을 넣으면 삭제된 비공개 글까지 노출 | 검색어를 SQL에 그대로 이어 붙임 (SQL 인젝션) | MyBatis `#{}` 바인딩 |
| 2 | 글이 쌓이자 목록 화면이 10초 이상, 메모리 부족 | 전체 글을 읽은 뒤 자바에서 10개만 자름 | DB에서 `OFFSET … FETCH` 로 10건만 조회 + 인덱스 |
| 3 | 목록 한 번에 쿼리 11번 | 글마다 댓글 수를 따로 조회 (N+1) | 집계 조인 한 번으로 |
| 4 | 하루 몇 번 오류가 나면 사이트 전체가 멈춤 | 예외 시 커넥션이 반환되지 않아 풀 고갈 | 스프링 트랜잭션이 커넥션 관리 |
| 5 | 주소창의 `page=abc` 한 번에 500 에러 화면 | 입력값 변환 예외 처리 없음 | 400 안내 화면 + 범위 보정 |
| 6 | 빈 제목·작은따옴표 제목에서 오류, GET으로도 글 등록 | 입력 검증 없음, 메서드 구분 없음 | Bean Validation + POST 전용 |
| 7 | 검색어에 넣은 스크립트가 다른 직원 브라우저에서 실행 | `<%= %>` 로 그대로 출력 (XSS) | Thymeleaf `th:text` 자동 이스케이프 |
| 8 | 화면 하나 고치면 다른 데가 깨짐 | JSP 안에 자바 로직이 섞여 있음 | 로직은 서비스로, 화면은 표시만 |

각 문제는 소스에 `[문제N]` / `[해결N]` 주석으로 표시해 두었습니다.

## 실행

```bash
cd modern-after
./gradlew bootRun
```

브라우저에서 http://localhost:8090/board 를 엽니다. 데모 데이터 1,000건이 들어 있습니다.

## 테스트

```bash
cd modern-after
./gradlew test
```

8가지 문제가 재발하지 않는지 확인하는 테스트 9개가 들어 있습니다
(`src/test/java/com/company/board/BoardMigrationTest.java`).
